# 業種別 飲食店LPデモ 3本 設計書

作成日: 2026-11-18

## 目的と背景

ポートフォリオには、飲食店LPの制作見本として「炭と旬の店 くゆり」(`demos/kuyuri/`)が1本だけ載っている。くゆりは高級和食(黒・金・明朝・縦書き)なので、見る人には「暗い高級店しか作れない人」に見えるおそれがある。

そこで業種と雰囲気がはっきり違う見本を3本追加し、**どんな業種・雰囲気のお店でも作れること**と、**どの業種でも「LPを見た人がそのまま予約できる」導線を組み込めること**を見せる。営業先の多くは地域の一般的な飲食店なので、そこで身近な業種を選んでいる。

## ゴール

- 3本それぞれが、見た目(色・書体・レイアウト・写真の扱い)でくゆりとも、ほかの2本ともはっきり違うこと
- 3本とも、ファーストビューの近くに予約導線(空席表示→日時・人数・コース選択→予約確認ダイアログ、満席ならキャンセル待ち)があること
- 予約導線のUIも業種に合わせて形を変えること(同じボードの色違いにはしない)
- `data.js` に1件ずつ追加し、ポートフォリオの一覧・詳細ページに載ること

## やらないこと

- 実際の予約処理(くゆりと同じく、確認ダイアログで「デモのため確定しません」と出して終わる)
- 3本共通のテンプレートやエンジンを作ること(見せたいのは「業種ごとに別のデザイン」なので、コードも各ページで独立させる)
- 予約システム(GAS)側の変更

## 避けたいこと(技術的に動いても失敗とみなす)

- 3本がくゆりの色違いに見えること
- 実在の店舗・チェーン・ブランドと誤解されること
- 写真が入っていない状態で一般公開されること(main へのマージは写真が入ってから)
- 予約システムにない機能を、あるように見せること(例:席種別・個室ごとの空席管理。予約システムは総座席数ベースなので、空席表示も総座席数ベースにする)

## 制約(既存のルールから)

- HTML1ファイル+同じフォルダの写真という構成で、ビルドもライブラリも使わない。読み込んでよいのは Google Fonts だけ
- `<meta name="robots" content="noindex">` を付ける。ページの上部(demo-bar)と下部(footer)に、架空店舗であること・写真がAI生成イメージであること・制作者へのリンク・飲食店予約システムへのリンク(`project.html?id=inshokuten`)を書く
- スマホからPCまでのレスポンシブ対応。`prefers-reduced-motion` で動きを止める。ボタンは `aria-pressed` などでアクセシブルにする
- スクリーンショット(`data.js` の `screenshot`)は、写真を入れた実ページを実際に開いて撮ったものだけにする。写真が入るまでは `screenshot` を設定しない

## 進め方の比較(選んだもの)

| 案 | 内容 | 長所と短所 |
|---|---|---|
| **A. 3本をそれぞれ独立したHTML1ファイルで作る(採用)** | くゆりと同じ構成を `demos/<slug>/` に3つ置く | 業種ごとに見た目を変えやすく、既存の構成と同じ。空席ロジックが3か所に重複するが、デモ用の短いコードなので問題ない |
| B. 共通のひな形と店舗ごとの設定 | 予約システムの「共通エンジン+CONFIG」と同じ考え方 | 中身の差し替えは楽だが、見た目まで共通化され「色違い」に見える。目的に反する |
| C. Artifactだけで公開 | portfolio に載せない | ポートフォリオに載らないので目的を果たせない |

## 写真の扱い(決定:仮の枠で作り、あとで差し替える)

- 写真の枠は、最終的なファイル名(`<slug>-hero.jpg` など)を参照する `<img>` で組む
- 画像が存在しない間は、枠に「写真:○○(イメージ)」というラベル付きの落ち着いた色の面を表示する。画像が読めない `<img>` は隠し、枠の背景とラベルが見える状態にする(壊れた画像アイコンは出さない)
- 画像を置けば、コードを変えずにそのまま表示が切り替わる
- 写真枠ごとに **ファイル名・縦横比・推奨サイズ・生成用プロンプト(日本語と英語)** の一覧を、各フォルダの `PHOTOS.md` に書いてお渡しする

## 3店の設計

店名・住所・電話はすべて架空。住所はくゆりと同じく「東京都架空区」の別の町にする。

### A. 大衆酒場「まるよし」 — `demos/maruyoshi/`

- **お店の設定**: 駅前の大衆酒場。焼き鳥・もつ煮・刺身・定番つまみ。宴会と飲み放題に力を入れている。総座席40席(座敷貸切最大40名)。営業 16:00〜24:00、日曜休み
- **雰囲気**: 明るく賑やか。赤提灯の赤、生成り、墨の3色を中心に、黄色を差し色に使う。見出しは極太の和文ゴシック(Dela Gothic One)、品書きの短冊は手書き風(Yusei Magic)。横書き。紙の質感、斜めに貼られた品書き短冊、角丸のハンコ風ラベル
- **ファーストビュー**: 赤提灯と店の外観の写真に、大きなキャッチコピー(例:「今日も、おつかれさん。」)と「宴会の空きを見る」ボタン
- **予約UI**: 1週間分の横スクロールの日付帯に、居酒屋の貼り紙らしく ◎○△× の記号で、夜の時間帯(17:00〜21:00)の空き具合を表示する。日付と時間を選ぶと人数(2〜20名、21名以上は電話)と宴会コースを選べる。満席ならキャンセル待ちに切り替わる
- **構成**: ヒーロー → 宴会の空き状況 → 宴会コース(飲み放題付き 3,500円/4,500円/5,500円、時間・品数) → 品書き(短冊風の一品料理、今月のおすすめは表示時の月で切り替え) → 店内(カウンター・テーブル・座敷) → ご予約案内 → アクセス
- **写真枠**: ヒーロー(赤提灯と外観)、焼き鳥、もつ煮、宴会の卓、座敷、カウンター

### B. 喫茶「ことり」 — `demos/kotori/`

- **お店の設定**: 住宅街の小さな喫茶店。自家製ケーキとハンドドリップ。**アフタヌーンティーは完全予約制**(1日3回 11:00/13:00/15:00、各2時間)。総座席16席。営業 9:00〜18:00、水曜休み
- **雰囲気**: 白と生成りを基調に、ミントとくすんだピンクを差し色に使う。丸ゴシック(Zen Maru Gothic)、余白を大きく取る。写真は角丸で、少しずらして重ねて配置する。軽くやわらかい印象
- **ファーストビュー**: アフタヌーンティーのスタンドの写真と「午後を、ゆっくり。」のようなコピー、「アフタヌーンティーを予約」ボタン
- **予約UI**: 2週間のカレンダーを表示し、各日に3回分の枠を小さな丸(空き・残りわずか・満席)で並べる。枠を選ぶと人数(1〜4名)とプラン(季節のアフタヌーンティー/ケーキセット席予約)を選べる。満席ならキャンセル待ち
- **構成**: ヒーロー → 季節のアフタヌーンティー(表示時の月で季節名を切り替え。例:「冬のいちごアフタヌーンティー」) → 予約カレンダー → いつものメニュー(モーニング・ランチ・ケーキ・ドリンク) → お店のこと → ご予約案内 → アクセス
- **写真枠**: ヒーロー(アフタヌーンティーのスタンド)、ケーキ、ハンドドリップ、窓辺の席、店の外観

### C. 炭火焼肉「ひのと」 — `demos/hinoto/`

- **お店の設定**: 黒毛和牛の一頭買いをうたう、仲間や家族向けの炭火焼肉店。総座席48席。営業 17:00〜23:00、土日祝は 11:30〜14:30 のランチもあり。火曜休み
- **雰囲気**: 黒と炎の赤・オレンジを使った、力強い現代的なデザイン。極太ゴシック(Zen Kaku Gothic New 900)と、数字や英字に細長いサンセリフ(Bebas Neue)。斜めの区切り線と大きな数字(価格・グラム)。くゆりの「静かな和の黒」に対して、「動きのある現代の黒」にする
- **ファーストビュー**: 網の上で焼ける肉のアップの写真に、大きなコピー(例:「焼く音から、うまい。」)と「空席を見る」ボタン
- **予約UI**: 日付タブ(今日〜6日後)と、時間ごとの縦リストを表示する。各行に「混み具合のバー」(総座席に対して何割埋まっているか)と残席数を出す。人数(1〜12名)とコース(上カルビコース/特選和牛コース/席のみ)を選べる。満席ならキャンセル待ち
- **構成**: ヒーロー → 空席 → こだわり(一頭買い・炭) → 部位図(牛のシルエットをインラインSVGで描き、部位を押すと説明と価格を表示) → コース → 一品メニュー → 店内 → ご予約案内 → アクセス
- **写真枠**: ヒーロー(網の上の肉)、和牛の盛り合わせ、炭火、コースの卓、店内

## 共通の実装方針

- 空席は、くゆりと同じく日付と時間帯から決まるサンプル値で表示する(同じ日付なら何度開いても同じ値)。定休日は日付の選択肢から外す
- 確認ダイアログには、選んだ内容と「デモのため予約は確定しません。実際のシステムでは…」の一文、「予約システムを見る」ボタンを表示する(くゆりの文面と合わせる)
- `data.js` には category「LP制作」で、くゆりと同じ形式で3件追加する(`demo`・`demoNote` あり、`screenshot` なし)

## 公開の手順

1. 作業ブランチ `claude/relaxed-euler-yg9e7d` に3本と `PHOTOS.md`、`data.js` の追記をコミットして push する(main には入れないので、GitHub Pages には公開されない)
2. ユーザーが `PHOTOS.md` をもとに写真を生成し、各フォルダに置く
3. 写真が入った状態で表示を確認し、スクリーンショットを撮って `data.js` の `screenshot` を追加する
4. main へマージして公開する(PR を作るかどうかは、その時点でユーザーに確認する)

## 制作者に任せる部分

- コピー・メニュー名・価格の細かい文言(上の例を目安に、業種らしく自然なものにする)
- 予約UIの細かい見た目と、スマホでの配置
- 架空の住所の町名・駅名(くゆりの「あかね町」とは別にする)
