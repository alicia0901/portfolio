# Portfolio

個人開発プロジェクトの一覧・詳細ページ。日々の課題を自分で解決するために作った、実働するシステム・ツール5件を紹介しています。

**🔗 Live: https://alicia0901.github.io/portfolio/**

## 使い方

`index.html` を直接ブラウザで開くだけで動作する(ビルド不要、依存関係なし)。一覧の各プロジェクトタイトル/「詳細を見る」から `project.html?id=<プロジェクトid>` の詳細ページに遷移する。

## 構成

```
.
├── index.html    … 一覧ページ(カテゴリフィルタ付き)
├── project.html  … 詳細ページの共通テンプレート(?id=<id> で表示内容を切り替え)
├── data.js       … 掲載する全プロジェクトのデータ(index.html/project.html 共通)
├── style.css     … 共通スタイル(デザイントークン・一覧/詳細ページのコンポーネント)
├── demos/        … ブラウザで直接動かせるデモの実体(このリポジトリの外にある元プロジェクトからのコピー)
│   ├── travel-expense-splitter/
│   └── umbrella-forecast/
├── card.html     … 電子名刺ページ
├── assets/
│   ├── card-qr.png       … card.html自身のURLを指すQRコード(build時にAPIで生成した静的画像)
│   └── alicia0901.vcf    … 「連絡先を保存」ボタンからダウンロードされるvCard
├── README.md
└── CLAUDE.md
```

紹介している5プロジェクトのうち、GAS製の業務システム(接骨院予約・飲食店予約)とCLIツール(netdiag)は、実店舗の設定やローカル環境に依存するためソースコード自体はこのリポジトリに含めていません(説明のみ掲載)。ブラウザ単体で動く2つのWebアプリ(旅費精算・傘予報)だけは `demos/` 配下にコードを複製し、実際に動くデモとして公開しています。

掲載データはすべて `data.js` の `PROJECTS` 配列に集約している。`index.html`・`project.html` はどちらも `<script src="data.js">` で読み込むだけで、データの二重管理は発生しない。

新しいプロジェクトを追加する場合は `data.js` の配列にオブジェクトを1件追記するだけでよい。

```js
{
  id: "project-slug",       // 詳細ページURL(project.html?id=xxx)に使う。一意にすること
  category: "Web App",      // 既存カテゴリ or 新規カテゴリ文字列
  title: "プロジェクト名",
  desc: "一言説明",
  story: "開発の背景・課題(なぜ作ったか)。任意項目、詳細ページにのみ表示",
  features: ["特徴1", "特徴2", "特徴3"],
  architecture: ["技術的な工夫・設計判断1", "工夫2"], // 任意項目、詳細ページにのみ表示
  stack: ["技術1", "技術2"],
  path: "フォルダ名/エントリーファイル", // 表示用テキスト。このリポジトリ内のパスとは限らない
  demo: "demos/フォルダ名/index.html", // このリポジトリ内で実際にブラウザ動作するデモがある場合のみ指定
  impact: {
    basis: "estimate", // 実測データがある場合のみ "measured"
    metrics: [
      { label: "指標名", before: "導入前の状態", after: "導入後の状態" }
    ]
  }
}
```

`demo` は、このリポジトリの `demos/` 配下に実体があり、相対パスとして機能する静的Webアプリにのみ設定する。バックエンドが必要なシステムやCLI/Pythonツールは単体では起動できないため設定しない。新しくデモ可能なWebアプリを追加する場合は `demos/<フォルダ名>/` にソースをコピーしてから `demo` を設定すること。

`impact`(導入前後の比較)は各カード・詳細ページに `before → after` の数値で表示する。**`basis: "estimate"` は実際に計測した数値ではなく、機能から推測した目安であることを示す内部フラグ**で、ページ上に個別バッジは出さない代わりに、一覧ページ上部の注記文(および `basis !== "measured"` のプロジェクトの詳細ページ下部の一文)でまとめて注記している。実際に計測・検証したデータがある場合のみ `"measured"` にする(現状すべてのプロジェクトが `"estimate"`)。推測値を実測データであるかのように見せないこと。

## 電子名刺 (card.html)

トップページから「🪪 電子名刺」で遷移できる、共有・印刷用の簡易プロフィールカード。ポートフォリオへの導線・メール・QRコード・vCardダウンロードのみのシンプルな構成。

`assets/card-qr.png` は `card.html` 自身のURL(`https://alicia0901.github.io/portfolio/card.html`)を指すQRコード画像で、外部APIで一度だけ生成して静的ファイルとして同梱している(ページ表示時に外部通信は発生しない)。名前・肩書き・QRの遷移先URLを変更した場合は、`card.html` の表示内容と `assets/alicia0901.vcf`・`assets/card-qr.png` を両方作り直すこと。
